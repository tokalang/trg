# trg v0.18.0 Release Notes

**Release**: `v0.18.0`<br>
**Release Date**: 2026-09-10<br>
**Target Platforms**: `linux-x64`, `macos-arm64`, `windows-x64`, `windows-arm64`<br>
**Toolchain**: Toka SDK 1.0.0-rc.11, Clang/LLVM, MSYS2 MinGW-w64 / CLANGARM64

## 1. Overview

`trg v0.18.0` 重点引入单文件符号视图（Single-File Symbol View）与语义范围可靠性增强，为 AI Agent 和开发者提供高保真、开箱即用的代码实体检索与展开能力：

1. **单文件符号视图 (`trg view <path> --symbol <SPEC> [--scope <SCOPE>]`)**:
   - 支持通过符号名精确查看函数、方法、类型等代码实体及其完整范围；
   - 支持 `--scope` 可选限定词消除同名符号歧义（如区分嵌套类方法与同名顶层函数）；
   - 严格遵循统一退出码规范：未找到符号返回退出码 1；多重候选歧义、语法不支持、扫描未完成及 I/O 错误返回退出码 2 并保持 stdout 纯净；
   - 歧义时在 stderr 输出候选列表及消除提示（`hint: specify --scope <SCOPE>`），且严格遵循 `--max-result-bytes` 输出预算限制；
2. **语义范围与定界符可靠性增强**:
   - 补齐方括号（`[` / `]`）及行尾反斜杠（`\`）的续行状态跟踪；未闭合时在 EOF 正确标识 `unknown` 状态并提供安全范围预览，避免误判为已完整闭合；
   - 多重装饰器语法下，行/字节预算收紧（例如 `--max-lines 1`）时智能锁定并保留核心声明行；
   - 单文件符号定位遵循 10MiB 输入读取上限保护（10MiB input read limit），并在 10 万行流式测试中保持严格稳定性；
3. **MCP `trg_view` 协议对齐与双版本兼容**:
   - MCP `trg_view` 工具原生支持 `symbol` 与 `symbol_scope` 参数，与 `line` / `lines` / `block` / `context` 保持严格互斥校验；
   - 完美兼容 MCP `2024-11-05` 与 `2025-11-25` 规范，结构化输出正交提供 `selection_status`、`range_status`、`output_status` 三元状态；
   - 在多重候选和错误情况下严格遵守 `max_result_bytes` 预算约束，并在超额时 fail-closed 返回错误信息与 `isError: true`；
4. **四平台 CI 严苛门禁覆盖**:
   - 新增针对单文件符号视图与语义范围的专项测试套件 `tests/test_view_symbol.py`；
   - 全面接入 Linux x64、macOS arm64、Windows x64 与 Windows arm64 四平台 CI 构建与测试矩阵。

## 2. Key Improvements & Detailed Specifications

### 1. 命令行符号视图与歧义消除 (CLI Symbol View & Disambiguation)
- **语法与调用**:
  ```bash
  trg view <path> --symbol <SPEC> [--scope <SCOPE>]
  ```
- **退出码规范**:
  - `0`: 成功精确匹配到单一符号并输出视图；
  - `1`: 仅当指定文件已成功扫描且未找到匹配符号时（`not_found`）；
  - `2`: 歧义多重候选（`multiple_candidates`）、语法不支持（`unsupported_syntax`）、扫描未完成/超限（`scan_incomplete`）、I/O 错误（`io_error`）及互斥参数冲突；
- **候选列表预算保护**:
  - 当存在多个重名符号时，输出候选行号与作用域信息，并在末尾给出消除歧义的 `hint`；
  - 候选输出受 `--max-result-bytes` / `max_result_bytes` 限制，超限时自动截断（`[and N more candidates omitted]`）或在最小诊断超标时 fail-closed。

### 2. 语义范围与定界符深度跟踪 (Semantic Range Reliability)
- **定界符完备性**:
  - 语法扫描深度器全面跟踪圆括号 `()`、花括号 `{}`、方括号 `[]` 及行尾反斜杠 `\`；
  - 缩进型语言（如 Python）仅在定界符深度归零且缩进安全回到外层基线（`is_clean_eof`）时，才判定为 `valid_indent_eof`；未闭合结构在 EOF 处标记为 `unknown` 状态并输出未知范围提示；
- **声明行优先级保证**:
  - 在多装饰器修饰的函数或类中，当预算（`--max-lines`）极小（如 1 行）时，优先输出核心声明行（如 `def foo():`），避免仅截断输出首个装饰器行。

### 3. MCP 协议与双版本规范 (Model Context Protocol Parity)
- **参数矩阵**:
  - `symbol` (string, optional): 待查找的符号名称；
  - `symbol_scope` (string, optional): 待限定的外层作用域名称；
- **状态报告**:
  - `selection_status`: `exact_match`, `multiple_candidates`, `not_found`, `unsupported_syntax`, `scan_incomplete`, `io_error`;
  - `range_status`: `observed_close`, `single_line`, `valid_indent_eof`, `eof_fallback`, `unknown`;
  - `output_status`: `complete`, `truncated_lines`, `truncated_bytes`, `target_exceeds_max_result_bytes`.
