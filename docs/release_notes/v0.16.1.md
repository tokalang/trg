# trg v0.16.1 Release Notes

**Release**: `v0.16.1`<br>
**Release Date**: 2026-09-08<br>
**Target Platforms**: `linux-x64`, `macos-arm64`, `windows-x64`, `windows-arm64`<br>
**Toolchain**: Toka SDK 1.0.0-rc.11, Clang/LLVM, MSYS2 MinGW-w64 / CLANGARM64

---

## 1. Overview

`trg v0.16.1` is a targeted patch release focused on package manager validation compliance and structured diagnostic ergonomics:

1. **Package Manager Validation Compliance (WinGet / Scoop / Homebrew)**: Bare invocation (`trg` with zero arguments) now prints full usage/help and exits with status code `0`, eliminating automated validation failures (`Validation-Executable-Error`) in package manager verification sandboxes while preserving exit code `2` for syntax and flag errors.
2. **Structured CLI Diagnostic Ergonomics**: Regular expression compilation failures in human CLI mode now emit a stable error code (`INVALID_REGEX`) paired with actionable self-healing guidance (`hint: fix the regex syntax; if literal text was intended, replace -E with -F`), while strictly isolating and preserving JSON and MCP error payload contracts.
3. **Full Qualification & Zero Regression**: 100% pass across all 174 qualification tests without regression.

---

## 2. Key Improvements & Fixes

### 1. 包管理器探活合规 (Bare Invocation Exit 0 for Package Managers)
- **无参调用规范对齐**:
  - 当以零参数直接调用 `trg` 时，打印标准帮助信息并将进程退出码设为 `0`；
  - 彻底消除 WinGet 官方沙箱与包管理器（WinGet、Scoop、Homebrew）在执行存活测试时因退出码非 0 产生的 `Validation-Executable-Error`；
  - 严谨保留标准选项语法错误（如缺少参数的 `trg -n`、未识别参数）的退出码 `2`，守住 POSIX 参数校验契约。

### 2. 结构化正则错误诊断与投影隔离 (Structured INVALID_REGEX & Projection Isolation)
- **终端人机交互增强**:
  - 非法正则编译失败时，终端 stderr 输出结构化稳定错误码与修复线索：
    ```text
    trg: INVALID_REGEX: missing closing ']'
    hint: fix the regex syntax; if literal text was intended, replace -E with -F
    ```
- **机器与 MCP 协议投影隔离**:
  - CLI JSON 模式（`--json` / `--json-compact`）分流保留既有 `trg: regex parse error: <msg>` stderr 投影；
  - MCP 服务端（`trg_search` / `format_errors`）依据诊断类型保留原始错误文本前缀，保持现有 JSON-RPC 数据载荷与 Schema 契约 100% 字节级兼容。
