## 1. Overview

`trg v0.19.0` 正式引入**无状态单文件视图续读与分页机制（Single-File View Continuation & Resumption）**。该机制专为长函数、长文件在有限上下文预算下的安全阅读设计，提供抗撕裂读取保障与严格的边界控制：

1. **单文件无状态续读与分页 (`--continuation` / `--continue <TOKEN>`)**:
   - 在 `range`、`block` 与 `symbol` 模式下原生支持显式续读分页（`--continuation`）；
   - 当内容被行数（`--max-lines`）或字节数（`--max-result-bytes`）截断时，自动生成携带状态的紧凑安全 Token（`trg-cont-v1.<payload>`）；
   - 支持通过 `trg view --continue <TOKEN>` 恢复阅读，按目标范围起点顺序分页展开；
2. **抗撕裂读取（Anti-Torn-Read）密码学校验**:
   - 续读凭据内嵌文件内容的 SHA-256 完整性摘要；
   - 续读恢复时重新校验目标文件哈希，若文件被外部修改立即安全拒绝（`torn_read_detected`），严防上下文不一致；
3. **JSON 自动裁剪预算收敛**:
   - 将动态生成的候选 Token 开销直接纳入窗口收敛迭代循环，只有当“最小 1 条记录 + 必要元数据 + Token”仍无法容纳时才 fail-closed，彻底消除紧预算下的误拒绝；
4. **Token 超限 Fail-Closed 与严格数值校验**:
   - Token 格式强制限定在 4096 字节安全上限内；若生成 Token 超限，在任何代码行输出前直接中止（CLI 退出码 2，MCP `isError: true`），确保 0 代码泄露；
   - 严苛校验 Token 内部行号与范围的数值合法性，拒绝浮点数、零、负数及范围矛盾伪造凭据；
5. **MCP 协议规范对齐与无续读状态隔离**:
   - 物理行范围输出对外统一对齐为规范的 `"range"` 模式，符合 MCP `outputSchema` 声明；向下兼容解析历史 `"lines"` 模式；
   - 在未开启续读时，回包严格 100% 隔离 Token 键值与计算开销，保持与旧版完全一致的精简元数据。

## 2. 技术边界与保留说明 (Technical Boundaries & Clarifications)

1. **RC11 Linux 命令行读取限制属于已知边界**:
   - Toka SDK 1.0.0-rc.11 在 Linux 平台通过 `/proc/self/cmdline` 读取命令行参数（固定 4096 字节缓冲区）。
   - 虽然 `trg` 的 Token 格式规范允许最大 4096 字节，但由于 Toka SDK 1.0.0-rc.11 在 Linux 平台读取 `/proc/self/cmdline` 采用了固定 4096 字节缓冲区，当包含超大 Token 的整体命令行超过该缓冲区时会遭遇参数截断并报错（`Option requires an argument: --continue`）。
   - **对于包含超长符号名/深度作用域的超大凭据，推荐优先使用 MCP 协议**（通过 stdin JSON-RPC 传输，无 argv 缓冲区限制）。测试套件接受此类报错是兼容已知运行环境边界，**不代表该 SDK 限制已被修复**。
2. **性能与输出开销说明**:
   - 本轮构建聚焦于契约正确性、密码学抗撕裂读取与严格边界防护，**尚未包含“非续读 symbol 视图跳过 SHA-256 计算”与“减少 CLI 凭据重复打印”的优化**。
   - 性能与 Token 开销维持当前基准（非续读 symbol 视图仍会进行 bounded 文件哈希；CLI stderr 仍会在状态指示与提示行输出凭据）。
