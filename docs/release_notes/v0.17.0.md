# trg v0.17.0 Release Notes

**Release**: `v0.17.0`<br>
**Release Date**: 2026-09-10<br>
**Target Platforms**: `linux-x64`, `macos-arm64`, `windows-x64`, `windows-arm64`<br>
**Toolchain**: Toka SDK 1.0.0-rc.11, Clang/LLVM, MSYS2 MinGW-w64 / CLANGARM64

---

## 1. Overview

`trg v0.17.0` 重点推进输入语义与管道行为对齐，并统一多子命令下的资源预算入口：

1. **跨平台 Stdin 自动探测与管道对齐**:
   - 当命令行未显式指定搜索路径，且标准输入连接到管道或常规重定向文件时，自动搜索 stdin（`-`）；
   - POSIX 下通过 `/dev/fd/0`（macOS/BSD）与 `/proc/self/fd/0`（Linux）查询描述符状态（区分 `S_IFIFO`/`S_IFREG` 与 `S_IFCHR`），Windows 下通过 `GetFileType` 判断句柄类型（`FILE_TYPE_PIPE`/`FILE_TYPE_DISK`）；
   - 探测过程不预读任何输入字节，避免因延迟管道（生产者慢速启动）而误判回退至遍历当前目录。
2. **默认模式迁移为正则表达式（破坏性变更）**:
   - CLI 默认搜索模式调整为正则表达式，与 `rg` 等主流工具的使用习惯保持一致；
   - **默认正则是破坏性迁移，固定文本搜索请使用 `-F`**：若检索内容包含正则保留字符（如 `.`、`*`、`[`、`(` 等）的固定文本，原脚本或习惯需显式附加 `-F` / `--fixed-strings` 开关；
   - 完全保留 `-E` / `--extended-regexp` 作为平滑兼容开关；`--symbol-variants` 在未显式传 `-E` 时按字面量安全展开；
   - **MCP Server 保持字面量兼容**：MCP 工具（`trg_search` 等）未指定模式时默认仍是 literal（字面量），仅当显式指定 `mode: "regex"` 时才启用正则，确保 AI Agent 与既有客户端零回归。
3. **统一资源预算入口（Search / View / Symbols）**:
   - `trg [PATTERN]`、`trg view <PATH:LINE>`、`trg symbols <PATH>` 全面统一支持 `--max-bytes` 与 `--max-result-bytes` 别名；
   - 明确各子命令预算计入内容、默认值（CLI 无限制）以及 `0` 截断终止与防御表现；
   - 在总帮助中提供标准多阶段工作流示例（`Search -> Symbols -> View`）。
4. **Ripgrep 差分测试套件与 CI 全平台覆盖**:
   - 建立独立差分测试 `tests/test_rg_differential.py`，覆盖 36 项核心管道输入、重定向、隔离、退出码 0/1/2 与输出非空/空断言；
   - 该差分套件已接入 Linux、macOS 以及 Windows x64、Windows ARM64 全量 CI 门禁矩阵；
   - 注：差分套件验证了当前 36 项关键场景的等价性，不代表涵盖 ripgrep 的全部高级参数与未移植语义。

## 2. Key Improvements & Migrations

### 1. 跨平台 Stdin 自动探测与路径决策 (Cross-Platform Stdin Detection)
- **自动定位标准输入**:
  - 无显式路径且检测到可读管道/文件重定向时，搜索目标设为 `-`；支持 `trg --files | trg PATTERN`、`git diff | trg PATTERN`、`trg PATTERN < sample.txt`；
  - 显式路径优先并忽略管道：`echo "foo" | trg -n "bar" .` 严格只搜索目录，不污染 stdin；
  - 空字符设备重定向（POSIX `/dev/null` 与 Windows `NUL`）不触发 stdin 搜索，自动回退到当前目录 `.`；
  - 显式指定 `-` 在空字符设备下严格搜索 stdin 并退出 1，绝不回退目录。
- **探测实现细节**:
  - POSIX: `posix_isatty(0)` 排除终端交互后，通过系统 `stat` 接口查询 `/dev/fd/0` 或 `/proc/self/fd/0`，断言 `S_ISFIFO` 或 `S_ISREG`；
  - Windows: 经由 C 兼容桥调用 `GetFileType(GetStdHandle(STD_INPUT_HANDLE))`，仅接受 `FILE_TYPE_PIPE` 或 `FILE_TYPE_DISK`。

### 2. 正则优先默认模式与字面量迁移 (Regex-First & -F Migration)
- **模式选择规则**:
  - 默认模式：正则表达式（Toka 正则引擎）；
  - 字面量模式：显式使用 `-F` / `--fixed-strings`；
  - 兼容模式：显式使用 `-E` / `--extended-regexp`；
  - `-E` 与 `-F` 互斥，同时传入报错退出码 2；
  - 正则语法错误诊断提示：
    ```text
    trg: INVALID_REGEX: missing closing ']'
    hint: fix the regex syntax; if literal text was intended, use -F (--fixed-strings)
    ```

### 3. 统一预算参数入口 (Unified Budget Options)
- **子命令统一对齐**:
  - 搜索、`view`、`symbols` 均接受 `--max-bytes <SIZE>` 与 `--max-result-bytes <SIZE>`；
  - 计费规则说明：
    - 搜索：统计规范匹配行与文件头字节；
    - View：统计格式化后的视图行字节；
    - Symbols：统计格式化后的符号大纲记录字节；
  - 帮助示例明确标出各阶段预算相互独立，由编排者或调用方按需分配总预算。
