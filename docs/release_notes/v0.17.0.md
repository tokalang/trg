# trg v0.17.0 Release Notes

**Release**: `v0.17.0`<br>
**Release Date**: 2026-09-10<br>
**Target Platforms**: `linux-x64`, `macos-arm64`, `windows-x64`, `windows-arm64`<br>
**Toolchain**: Toka SDK 1.0.0-rc.11, Clang/LLVM, MSYS2 MinGW-w64 / CLANGARM64

## 1. Overview

`trg v0.17.0` is a major capability and input ergonomics release establishing standard search workflow compatibility and unified resource budgets:

1. **Cross-Platform Stdin Automatic Detection & Pipeline Parity**:
   - Running `trg PATTERN` with piped stdin or redirected file input (`< file.txt`) now automatically targets standard input without requiring explicit path arguments.
   - Non-destructive OS-level descriptor detection (`fstat`/`S_ISFIFO` on POSIX, `GetFileType`/`FILE_TYPE_PIPE`/`FILE_TYPE_DISK` on Windows) ensures delayed producers never misroute searches to the current directory.
2. **Regex-First Pattern Search Alignment**:
   - Modernized CLI search mode to default to regular expressions, matching user expectations from `rg` and standard UNIX tools.
   - `-F` (`--fixed-strings`) explicitly selects high-performance literal string matching.
   - Backward compatibility preserved: `-E` (`--extended-regexp`, `--regex-mode`) remains supported as an explicit regex flag.
3. **Unified Resource Budget Entry Across Subcommands**:
   - All three primary subcommands—Search, `view`, and `symbols`—now universally accept `--max-bytes` and `--max-result-bytes` aliases.
   - Clarified explicit accounting rules and stop behaviors: CLI defaults to unlimited; passing `0` triggers immediate stop / budget cutoff notice.
   - Added canonical multi-stage workflow guidance (`Search -> Symbols -> View`) to CLI help.
4. **Hardened Ripgrep Parity Test Suite**:
   - `tests/test_rg_differential.py` expanded to 36 tests validating multiset match equivalence, file counts, exact exit codes (0, 1, 2), delayed pipelines, and file redirection against `rg`.
5. **Full Qualification & Zero Regression**:
   - 100% pass across all 176 qualification tests on both package builds and direct compilations.

## 2. Key Improvements

### 1. 跨平台 Stdin 自动探测与管道对齐 (Cross-Platform Stdin Detection)
- **输入流自动识别**:
  - 当未指定搜索路径且终端输入来自管道或文件重定向时，自动将搜索目标置为标准输入（`-`）；
  - 支持管道组合链：`trg --files | trg PATTERN`、`git diff | trg PATTERN`、`trg PATTERN < sample.txt`；
  - 显式指定 `-` 仍保持最高优先级。
- **无损元数据探测机制**:
  - POSIX: 通过 `fstat(0, &st)` 判定 `S_ISFIFO(st.st_mode)` 或 `S_ISREG(st.st_mode)`；
  - Windows: 通过 `GetFileType(GetStdHandle(STD_INPUT_HANDLE))` 判定 `FILE_TYPE_PIPE` 或 `FILE_TYPE_DISK`；
  - 探测过程不预读任何字节数据，延迟管道（如生产者休眠后再写入）绝不回退至遍历目录。

### 2. 正则优先默认模式与平滑兼容 (Regex-First Pattern Matching)
- **CLI 默认正则匹配**:
  - 无需再显式传入 `-E`，所有合法的正则表达式模式开箱即用；
  - 纯文本检索使用 `-F` / `--fixed-strings`，启用极速 Boyer-Moore / 字面量匹配引擎；
  - 既有脚本若使用 `-E` / `--extended-regexp` 保留平滑兼容，不中断自动化流程；
  - 正则语法报错提示自动引导用户根据意图选用 `-F`：
    ```text
    trg: INVALID_REGEX: missing closing ']'
    hint: fix the regex syntax; if literal text was intended, use -F (--fixed-strings)
    ```

### 3. 统一预算参数入口 (Unified Budget Options)
- **全命令参数对齐**:
  - `trg [PATTERN]`、`trg view <PATH:LINE>`、`trg symbols <PATH>` 三处均同时支持 `--max-bytes <N>` 与 `--max-result-bytes <N>`；
  - 统一帮助文档说明：明确计入内容、默认值（CLI 无限制，MCP 按协议指定）以及 `0` 代表立即截断终止；
  - 帮助文档附带标准多阶段组合工作流示例：
    ```text
    Search -> Symbols -> View workflow:
      trg "Query" src/ --max-total-matches 10
      trg symbols src/file.tk
      trg view src/file.tk:42 --block
    ```
