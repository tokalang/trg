# trg v0.15.0 Release Notes

**Release**: `v0.15.0`<br>
**Release Date**: 2026-09-07<br>
**Target Platforms**: `linux-x64`, `macos-arm64`, `windows-x64`, `windows-arm64`<br>
**Toolchain**: Toka SDK 1.0.0-rc.11, Clang/LLVM, MSYS2 MinGW-w64 / CLANGARM64

---

## 1. Overview

`trg v0.15.0` is a milestone release delivering native Windows Tier-1 support across `x86_64` (`windows-x64`) and `aarch64` (`windows-arm64`), alongside full support for Linux and macOS. Windows executables are standalone, dependency-free binaries linked solely against core OS system DLLs, verified via strict PE import table auditing on native runners.

---

## 2. Key Improvements & Fixes

### 1. 原生 Windows 平台支持 (Native Windows x64 & ARM64)
- **Zero Third-Party DLLs (系统级依赖审查)**:
  - **Windows x64**: 实际导入表依赖为 `bcrypt.dll`、`kernel32.dll`、`msvcrt.dll`、`shell32.dll`、`ws2_32.dll`。
  - **Windows ARM64**: 实际导入表依赖为上述系统组件以及系统标准的 `api-ms-win-crt-*` Forwarders。
  - 经独立 PE 结构解析审查，两端均 **完全排除** `libwinpthread*`、`libgcc*` 等任何第三方运行时 DLL，达成完全独立的绿色发布二进制。
- **Strict PE Import Table Auditing**: 自动化资格测试套件包含 `tests/verify_standalone_binary.py`，通过解析 COFF Optional Header 与 `IMAGE_IMPORT_DESCRIPTOR` 结构体，严格白名单约束系统 DLL 并阻断非法外部依赖。

### 2. 管道与 I/O 错误处理加固 (Hardened Windows Pipe & Broken Pipe Semantics)
- **Precise EPIPE Normalization**: Windows C 桥接层 (`trg_win_compat.c`) 严格检测句柄类型是否为管道，且仅在确认发生 `ERROR_BROKEN_PIPE` 或 `ERROR_NO_DATA` 时归一化为 `EPIPE`，彻底防止普通 `EINVAL` 或陈旧 `GetLastError()` 错误码导致误判成功退出。
- **POSIX Output Layer Isolation**: 公共输出层 (`src/posix.tk`) 仅处理标准 `EPIPE` (32) 退出码 0，普通写入失败严格返回退出码 2。

### 3. 严格路径解析与驱动器识别 (Strict Windows Path Resolution)
- Windows 路径解析在目标盘符不可达或无效时严格返回 `Result::Err`，彻底杜绝猜解 identity 或静默回退根目录的行为。

### 4. WinGet 官方清单规范 (Windows Package Manager Distribution)
- 自动化生成符合 WinGet 1.9.0 标准的多架构清单 (`Tokalang.trg`)，指定 `MinimumOSVersion: 10.0.18362.0` 并采用 portable ZIP 解压映射。
- **当前状态说明**：当前已完成清单生成及独立契约测试验证。上架官方目录需待向 `microsoft/winget-pkgs` 提交 PR 并经官方 review 合并；在官方目录收录前，Windows 用户请直接下载使用已认证的官方 ZIP 压缩包。

### 5. 四平台统一发布门禁 (Authoritative Four-Platform CI Release Gate)
- 正式发布资格严格以 GitHub Actions 原生 Runner（`ubuntu-22.04`、`macos-15`、`windows-2025`、`windows-11-arm`）的自动化执行结果作为唯一依据。
- 交付物严格执行 6 件套交付标准（`linux-x64.tar.gz`、`macos-arm64.tar.gz`、`windows-x64.zip`、`windows-arm64.zip`、`trg-0.15.0.tar.gz`、`SHA256SUMS`），杜绝覆盖上传。
- **自动化核验范围说明**：CI 内的 `post-publish-verify` 负责校验发布草稿状态与资产存在性；草稿公开后需进一步执行端到端匿名下载、SHA-256 摘要核对与消费者真实运行验证。
