# trg v0.14.1 Release Notes

**Release**: `v0.14.1`<br>
**Release Date**: 2026-09-07<br>
**Target Platforms**: `linux-x64`, `macos-arm64`<br>
**Toolchain**: Toka SDK 1.0.0-rc.11

---

## 1. Overview

`trg v0.14.1` is a focused maintenance and stability release. It addresses scanner memory scaling during non-context searches, hardens the universal regression test harness and qualification suite, and formally establishes the search and perception contract baseline.

---

## 2. Key Improvements & Fixes

### 1. 降低无上下文扫描中的内存增长 (Scanner Memory Scaling Reduction)
- **Problem**: In `v0.14.0`, file scans constructed full `LogicalLine` objects on every line even when no context lines (`-A`, `-B`, `-C`, `--block`, `--scope`) were required. Under large file streaming, this caused the process RSS to scale with total file size.
- **Fix**: In [`src/scanner.tk`](file:///Users/zhyi/GitDP/tokalang/trg/src/scanner.tk), introduced an early short-circuit for non-matching lines when context accumulation is inactive, bypassing intermediate line object allocations.
- **Empirical Measurement** (macOS ARM64, repetitive isolated `wait4` measurements on 2 / 6 / 18 MiB structured files):
  - **v0.14.0 Baseline**: RSS measured at 5.02 / 9.31 / 22.48 MiB (4.48x expansion ratio; delta slope $\approx 1.09\text{ MiB/MiB}$).
  - **v0.14.1**: RSS measured at 2.67 / 2.89 / 2.98 MiB (1.12x expansion ratio; delta slope $\approx 0.02\text{ MiB/MiB}$).
  - *Note*: Memory bounds are reported as empirical observations under specified test environments and scale profiles without unwarranted claims of absolute constant bounds or runtime ARC lifecycle behavior.
- **Differential Output Parity**: Verified via 16 byte-exact test vectors comparing `v0.14.0` against `v0.14.1`. Zero functional or formatting drift was observed, with variations strictly limited to declared server version metadata in MCP protocol initialization.

### 2. 回归与资格测试门禁强化 (Test Harness & Qualification Hardening)
- **Universal Regression Matrix**: Expanded to 38 functional assertions spanning literal meta-characters, RFC 3629 UTF-8 handling, case folding, multiline streams, LF/CRLF line termination, trailing newlines, block boundaries, and file sizes.
- **Canonical UTF-8 Budget Verifier**: Hardened independent billing accounting in test suites to enforce canonical UTF-8 bytes without relying on default Python ASCII escaping (`\uXXXX`), guaranteeing precision for CJK and Emoji contents under byte budgets.
- **Raw Byte Protocol Parity**: MCP stream diffing preserves trailing newlines and binary byte streams to prevent undetected transport drift.
- **Standalone Binary Deliverable Verifier**: Added [`tests/verify_standalone_binary.py`](file:///Users/zhyi/GitDP/tokalang/trg/tests/verify_standalone_binary.py) to independently verify extracted binary packages, smoke tests, and the universal matrix directly on release deliverables.

## 3. Documented Contract Gaps (已知契约缺口)

In accordance with [`docs/contracts/search_and_perception_contract.md`](file:///Users/zhyi/GitDP/tokalang/trg/docs/contracts/search_and_perception_contract.md) and the universal regression matrix definitions:

- **GAP-001 (未知类型 --code-only 误过滤 URL 等非代码文本)**:
  Non-code files (e.g. `service.log`) fall back to `Generic` lexical dialect, erroneously treating `//` inside URLs as single-line comments and silently suppressing matching lines under `--code-only`.
- **GAP-002 (未知类型 --block 误生成结构)**:
  Plain text or unsupported file formats containing `{}` fall back to `Brace` syntax family, improperly synthesizing structured code block headers (`[block: L...-L...]`) around matches.
- **Lexical/Symbol Scope Baseline**:
  Scope perception in `trg` remains lexical and symbol-based; full AST/CST semantic parsing is intentionally not part of this release.

## 4. Platform & Ecosystem Status

- **macOS & Linux**: Full tier-1 support for `macos-arm64` and `linux-x64`, verified via dual-platform CI under Toka SDK 1.0.0-rc.11.
- **Windows / WSL**: Technical feasibility research completed ([`docs/research/windows_and_wsl_feasibility.md`](file:///Users/zhyi/GitDP/tokalang/trg/docs/research/windows_and_wsl_feasibility.md)). Native Windows deliverables are deferred to a dedicated porting cycle; WSL2 is recommended for Windows environments at this stage.
- **Package Registry**: Available via Toka Registry (`pkg.tokalang.dev`) following official release publication and live registry deployment.
