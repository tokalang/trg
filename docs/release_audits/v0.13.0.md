## 1. Executive Summary

`trg v0.13.0 (Progressive Perception Engine)` advances from purely coordinates-based search into a progressive two-stage perception loop for AI agents and human developers:
1. **Centered KWIC Snippet Projection (`--snippet` / `--kwic`, `--snippet-chars <NUM>`)**: Formats matching lines centered around target tokens with `...` truncation markers, adjacent window fusion ($\le 10$ character gap), and distant multi-match bridging (` [...] `). Eliminates token bloat on multi-kilobyte lines while retaining pinpoint match context.
2. **Stateless Zero-Latency Point Hydration (`trg view`)**: Enables instantaneous $O(1)$ disk reads to inspect target lines with context (`trg view <path>:<line> [-C N]`), syntactic code blocks (`trg view <path>:<line> --block`), or physical line ranges (`trg view <path> --lines <start>-<end>`).
3. **Dedicated MCP Hydration Tool (`trg_view`) & Typed Snippet Perception**: Exposes `trg_view` in Model Context Protocol with zero session state caching or memory drift, and augments `trg_search` with typed `snippet: bool` and `snippet_chars: integer` options.
4. **Normalized Declaration Scope Breadcrumbs**: Eliminates trailing dangling open parens (`(`) and parameter slicing across all supported syntax families, cleanly normalizing callables to `async fn name()` and types to `class Name` / `struct Name`.
5. **Deterministic Block Delimiter Pairing & Fail-Closed Runaway Guard**: Ensures `block_range: [start, end]` emitted by `--block` in JSON and MCP is strictly safe for automated code refactoring. Adheres to fail-closed principles: if a block is truncated or its delimiter cannot be closed deterministically before a sibling definition begins, `block_range` evaluates strictly to `null` (`None`).

## 2. Key Architecture & Protocol Specifications

### 2.1 KWIC Snippet Architecture (`src/snippet.tk`)
- **UTF-8 Character Alignment**: Boundaries are computed using strict character counts rather than raw byte offsets, snapping safely to UTF-8 character heads (`byte & 0xC0 != 0x80`).
- **Window Fusion**: When matches on the same line have overlapping or adjacent windows separated by 10 characters or fewer, their windows are fused into a continuous slice.
- **Window Bridging**: When matches are separated by more than 10 characters, independent windows are connected via ` [...] `, preventing token explosion while conveying distance.

### 2.2 Stateless Hydration Engine (`src/view.tk`)
- **Chunked File Streaming**: Reads file lines with bounded 64KB libc chunked buffers without loading full files into memory or building global AST indexes.
- **Syntactic Block Perception**: Reuses syntax heuristics to locate enclosing brace depth or indentation boundaries on the target line, printing clear `[block: L{start}-L{end}]` demarcation.
- **Rigorous CLI & MCP Guards**: Validates 1-based line bounds against physical file length, enforces boundary ordering (`start <= end`), and prevents filesystem root traversal escapes in MCP mode.

### 2.3 MCP Parity & Tool Registration (`src/mcp_schema.tk`, `src/mcp.tk`)
- **`trg_view` Tool**: Registered with input schema defining `path`, `line`, `context`, `block`, and `lines`. Returns formatted text slices directly with `isError: false` or protocol error messages.
- **`trg_search` Snippet Schema**: Added `snippet` and `snippet_chars` with two-way reflection into `effective_query`, CLI translation, and protocol schema v2.

### 2.4 Deterministic Block Delimiter Pairing & Fail-Closed Runaway Guard (`src/syntax.tk`, `src/scanner.tk`, `src/view.tk`)
- **`BlockDelimiter` State Machine**: Tracks `Brace` (`{}`) vs `Paren` (`()`).
- **Keyword-Strict Binding**: Declarations beginning with `fn`, `def`, `class`, `interface`, `trait`, etc., bind strictly to `BlockDelimiter::Brace` regardless of multi-line parameter lists. Toka `shape` and assignment expressions bind to `BlockDelimiter::Paren`.
- **Single-Line Block Self-Closure**: Declarations like `pub shape Empty ()` and `fn noop() {}` are detected as immediately self-closed, avoiding false-positive runaway guards on sibling definitions.
- **Fail-Closed Runaway Guard**: When a sibling definition appears before depth returns to $\le target\_depth$, the runaway block is immediately closed with `block_range_valid = false` (`null`).
- **Truncation Fail-Closed**: Blocks truncated by `--max-block-lines` record `block_truncated: true` and assign `block_range = None` (`null`) to prevent dangerous partial deletion during automated editing.
- **`usize` Underflow Safety**: All depth decrements are guarded with `depth > 0`.
