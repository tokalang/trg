## 5. Memory Scaling & Isolated RSS Measurement

Isolated peak RSS measured per-process using `os.fork` and `os.wait4` with SIGKILL-backed timeout reaper.

### 5.1 File Size Scaling (Fixed Line Length 100 chars, Match Density 1/1000)
- **Benchmark Configuration**:
  - Scales: 2 MiB, 6 MiB, 18 MiB (9x file size expansion, 16 MiB delta)
  - Repetitions: 3 runs per scale after initial warmup, median recorded
  - Gate Criterion: Memory growth ratio across 9x expansion $< 3.0\text{x}$
- **Empirical Measurements**:
  - **Public Release `v0.14.0`**:
    - 2 MiB: 5.55 MiB
    - 6 MiB: 10.19 MiB
    - 18 MiB: 23.53 MiB
    - Delta: +17.98 MiB RSS across +16.0 MiB input ($\Delta\text{RSS}/\Delta\text{Size} \approx 1.12 \text{ MiB/MiB}$)
    - Ratio: **4.24x** (Gate: **FAIL**)
  - **Patch Candidate `v0.14.1-rc`**:
    - 2 MiB: 3.47 MiB
    - 6 MiB: 3.62 MiB
    - 18 MiB: 3.98 MiB
    - Delta: +0.51 MiB RSS across +16.0 MiB input ($\Delta\text{RSS}/\Delta\text{Size} \approx 0.03 \text{ MiB/MiB}$)
    - Ratio: **1.15x** (Gate: **PASS**)

### 5.2 Long-Line Scaling ($T_{16}/T_4$ Time Ratio)
- **4 MiB Line**: Median scan time **0.0223s**
- **16 MiB Line**: Median scan time **0.0714s**
- **Scaling Ratio**: **3.21x** (Linear theoretical limit $\approx 4.0\text{x}$, quadratic threshold $\ge 16.0\text{x}$)
- **Verdict**: **PASS**. Confirms $O(L)$ linear performance with zero quadratic degradation.

## 7. Audit Conclusions & Recommendations

1. **v0.14.0 Release Integrity**:
   - The public `v0.14.0` binary is fully qualified for general search, boundary control, case modes, multi-pattern, UTF-8 offsets, MCP search/view budgets, and long-line scaling.
   - The public release does not meet the strict streaming constant-bound memory gate ($< 3.0\text{x}$ over 9x file size expansion) due to unoptimized logical line buffering.
2. **v0.14.1 Patch Readiness**:
   - The scanner optimization (`src/scanner.tk:851`) solves the memory scaling issue, reducing peak RSS from 23.53 MiB to 3.98 MiB on 18 MiB files and achieving a 1.15x scaling ratio.
   - The patch preserves 100% bit-for-bit output parity across all CLI and MCP test vectors.
   - Recommended to be packaged and released as `v0.14.1` following standard release protocol without altering existing tags.
