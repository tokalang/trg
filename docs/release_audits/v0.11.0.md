## 1. Executive Summary

`trg v0.11.0` introduces the **Canonical `trg-mcp-result-v2` Schema** and an orthogonal **Presentation Projection Layer**. It decouples canonical evidence identity from presentation layout, guarantees strict canonical budget purity, maintains atomic batch preflights, enforces strict stdin isolation in MCP stdio mode, and implements a layered deduplication contract between CLI and MCP.

### Key Capabilities & Architectural Enhancements:

1. **Canonical `trg-mcp-result-v2` Schema**:
   - Deduplicated path interning table (`files[]`) using lexical `identity_key` normalization.
   - Chronological execution segments (`segments[]`) mapping `file_id` and explicit execution pass (`pass: "all" | "definitions" | "usages"`).
   - Path-free `InternedRecord` structures eliminating duplicate URI payload waste.

2. **Presentation Projection Layer**:
   - Orthogonal presentation styling: `--heading` (grouped) and `--no-heading` (flat).
   - Dynamic path styling: `--path-style=as-given`, `workspace-relative`, `absolute`.
   - **Canonical Budget Purity**: `--max-result-bytes` bounds structured JSON evidence; switching presentation layouts between `grouped` and `flat` alters only human-readable text blocks, while canonical evidence and total match counts remain 100% byte-for-byte identical.

3. **Layered Target Deduplication Contract**:
   - **CLI Mode (`deduplicate_targets = false`)**: Strictly adheres to the traditional Unix/ripgrep contract. Passing duplicate path arguments scans the file multiple times predictably (e.g. `trg pat file file` emits matches twice, matching `rg`).
   - **MCP Mode (`deduplicate_targets = true`)**: Agent-safe by default. Collapses path aliases and duplicate directory references to conserve LLM context windows, tokens, and compute.
   - **Explicit Flags**: Supports `--deduplicate-targets` and `--no-deduplicate-targets` across CLI and MCP `args`. Reflects active status in MCP `effective_query.deduplicate_targets`.

4. **MCP Stdin Rejection & JSON-RPC Session Stream Preservation**:
   - In MCP stdio mode, searching `stdin` (`"-"`, `path: "-"`, `paths: ["-"]`, positional `"-"`, `-f -`, `-f-`, `--file=-`, attached `-efoo`, `--regexp=foo`, etc.) is strictly forbidden and rejected with code `-32602`:
     ```text
     stdin path/pattern source '-' is unavailable in MCP stdio mode
     ```
   - Requires typed `pattern` or `patterns`; raw pattern source options in `args` are completely disallowed.
   - Guarantees persistent session stream preservation: subsequent JSON-RPC calls (such as `ping`) are never consumed by stdin file readers.

5. **CLI Stdin Parity (`<stdin>`)**:
   - Normalized stdin display path to `"<stdin>"` with `PathKind::Stdin`.
   - 1:1 ripgrep parity: `-H` prefixes `<stdin>:line:match`, single-file default suppresses prefix (`line:match`), and `--json` records `"path":{"text":"<stdin>"}`.

6. **Streaming Render-and-Discard Memory Safety**:
   - CLI mode streams matches directly to standard output without holding record buffers in memory.
   - Memory footprint is bounded by $\mathcal{O}(\text{selected\_files} + \text{longest\_line} + \text{context\_buffer})$ and verified via isolated child process RSS under 50MB for 10,000 matches.

## 3. Two-Phase Release Sequence

To prevent installer broken windows where `install.sh` downloads an unreleased version:

1. **Pre-Release State**:
   - `install.sh` default `VERSION` is pinned to current public release `v0.10.0`.
   - `tests/verify_installer.py` validates `v0.10.0`.
   - `.github/workflows/release.yml` defaults to `v0.10.0`.
2. **Release Stage 1**:
   - Push tag `v0.11.0`.
   - GitHub Actions builds Linux x64 and macOS ARM64 standalone binaries.
   - Upload all assets and `dist/SHA256SUMS` to GitHub Release `v0.11.0`.
   - Publish `trg@0.11.0` source package to Toka Registry.
3. **Release Stage 2**:
   - Verify public HTTP 200 availability of binary downloads and checksums.
   - Submit independent commit bumping `install.sh` and workflow defaults to `v0.11.0`.
